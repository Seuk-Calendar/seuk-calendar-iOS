# Review PR

`.agents/rules/code-review-convention.md`를 기준으로 Pull Request를 리뷰하는 스킬입니다.

기본 대상은 **이미 열려있는 PR**입니다.

## 트리거 조건

다음 상황에서 이 스킬을 사용합니다.

- 사용자가 PR 리뷰를 요청한 경우
- 머지 전 품질 점검(아키텍처/DI/테스트/린트)을 요청한 경우

## 실행 모드

1. **workflow 모드 (`issue-to-pr-workflow`에서 호출)**
   - 리뷰 결과를 PR 코멘트로 **자동 등록**합니다.
2. **직접 호출 모드 (사용자가 `review-pr`만 요청)**
   - 리뷰 후 사용자에게 반드시 아래 질문을 합니다.
   - `코멘트로 남길까요?`
   - 사용자가 동의하면 코멘트를 등록하고, 거부하면 텍스트 결과만 보고합니다.

## 실행 단계

### 1. 리뷰 대상 PR 확인

1. 현재 브랜치 기준 열려있는 PR 확인
   ```bash
   gh pr status
   ```
2. 필요한 경우 특정 PR 조회
   ```bash
   gh pr view <number> --json number,title,url,state,headRefName,baseRefName,headRefOid
   ```
3. PR 상태가 `OPEN`이 아니면 리뷰를 중단하고, 열려있는 PR을 먼저 준비하도록 안내합니다.

### 2. 변경 범위 수집

리뷰 범위는 **대상 PR 기준**으로 고정합니다.

```bash
gh pr diff <number> --name-only
gh pr diff <number>
```

리뷰 대상은 코드 파일 우선, 문서는 보조로 확인합니다.

### 3. 컨벤션 체크리스트 적용

`.agents/rules/code-review-convention.md`의 항목을 아래 순서로 점검합니다.

1. 아키텍처/레이어/의존성(DI)
2. 에러 처리/접근 제어/네이밍
3. View/ViewModel 역할 분리
4. 테스트 유무 및 회귀 위험
5. 빌드/린트 상태(가능한 범위에서 로컬 검증)

### 4. 이슈 분류 기준

- `P0`: 빌드 실패, 크래시, 데이터 손상 가능성
- `P1`: 기능 오동작, 사용자 영향 높은 논리 결함
- `P2`: 유지보수성 저하, 아키텍처 규칙 위반, 테스트 공백
- `P3`: 스타일/문서 개선 권고

### 5. 리뷰 결과 작성 형식(공통)

리뷰 결과는 아래 순서를 반드시 따릅니다.

1. **Findings (우선순위 순)**
   - 파일 경로 + 라인
   - 문제 설명
   - 영향도
   - 수정 제안
2. **Open Questions / Assumptions** (있을 때만)
3. **요약** (한두 줄)

### 6. PR 코멘트 등록 규칙

1. workflow 모드에서는 Finding을 PR 코멘트로 자동 등록합니다.
2. 직접 호출 모드에서는 사용자 동의 후에만 코멘트를 등록합니다.
3. 코멘트 제목은 `[P0]`, `[P1]`, `[P2]`, `[P3]` 우선순위를 앞에 붙입니다.
4. 파일/라인을 특정할 수 있으면 리뷰 코멘트(라인 코멘트)로 등록합니다.
5. 파일/라인을 특정하기 어렵다면 PR 일반 코멘트로 등록합니다.

리뷰 코멘트(라인 코멘트) 예시:

```bash
gh api repos/<owner>/<repo>/pulls/<pr-number>/comments \
  -f body='[P1] 문제 설명 ...' \
  -f commit_id='<head-sha>' \
  -f path='path/to/file.swift' \
  -F line=120 \
  -f side='RIGHT'
```

PR 일반 코멘트 예시:

```bash
gh pr comment <number> --body '[P2] 테스트 공백이 있습니다 ...'
```

### 7. 결과 보고 형식

1. 대상 PR: 번호, 제목, URL
2. Findings 목록(우선순위 순)
3. 코멘트 등록 여부
4. 코멘트 등록 시: comment id/url 목록
5. 미등록 시: 미등록 사유(사용자 거부/라인 정보 부족/권한 이슈 등)

## 예외 처리

- 로컬에서 빌드/테스트를 실행할 수 없으면 이유를 명시하고, 정적 리뷰 결과만 제공합니다.
- 변경 파일이 너무 많으면 사용자 영향도가 큰 모듈부터 우선 리뷰하고 범위를 명시합니다.
- 관련 규칙 문서가 없거나 경로가 변경됐으면 누락 사실을 보고하고 일반 리뷰 기준으로 진행합니다.
- 열려있는 PR을 찾지 못하면 코멘트 등록 없이 리뷰 텍스트 결과만 제공하고 종료합니다.
