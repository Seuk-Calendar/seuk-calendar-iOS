# Create Rule

`rules` 디렉토리에 새 규칙 문서를 일관된 형식으로 추가하고, 참조 지점을 함께 동기화합니다.

## 트리거 조건

다음 상황에서 이 스킬을 사용합니다.

1. 사용자가 새로운 규칙/컨벤션 문서 추가를 요청한 경우
2. 기존 규칙만으로 커버되지 않는 새 작업 기준이 필요한 경우
3. `.agents/rules/*.md`에 새 파일을 만들어야 하는 경우

## 실행 단계

### 1. 규칙 요구사항 확정

아래 정보를 먼저 확정합니다.

- 규칙 주제 (예: 테스트 컨벤션, 릴리즈 컨벤션)
- 적용 대상 (예: 전체 프로젝트, 특정 모듈, 특정 작업)
- 반드시 지켜야 할 규칙 항목
- 포함할 예시 (좋은 예/나쁜 예)

**IF** 규칙 범위가 모호하면:
→ 파일 생성 전에 사용자에게 한 줄로 범위를 확인합니다.

### 2. 파일명 결정 및 중복 검사

파일명은 기본적으로 `kebab-case` + `.md`를 사용합니다.

- 권장 패턴: `<topic>-convention.md`
- 예시: `test-convention.md`, `release-convention.md`

중복 여부를 확인합니다.

```bash
ls -la .agents/rules
test -f ".agents/rules/<file-name>.md" && echo "exists"
```

**IF** 동일 파일이 이미 존재하면:
→ 신규 생성 대신 기존 파일 업데이트로 전환할지 사용자 의도를 확인합니다.

### 3. 룰 파일 생성

신규 파일을 생성하고 핵심 섹션을 채웁니다.

권장 템플릿:

```markdown
# <Rule Title>

## 목적
- ...

## 적용 범위
- ...

## 규칙
- ...

## 예시
- 좋은 예: ...
- 나쁜 예: ...

## 체크리스트
- [ ] ...

## 참고
- ...
```

### 4. 문서 인덱스 반영

새 규칙이 탐색 가능하도록 `.agents/INDEX.md`의 **컨벤션** 섹션에 항목을 추가합니다.

- 문서명
- 사용 시점
- 경로 (`.agents/rules/<file-name>.md`)

### 5. 규칙 자동 주입 매핑 반영 (필요 시)

새 규칙이 프롬프트 키워드 기반 자동 주입 대상이라면 아래 파일을 함께 수정합니다.

1. `.agents/skills/check-rules/SKILL.md`
   - 키워드 매핑 표/목록에 새 규칙 추가
2. `.claude/hooks/check-rules.sh`
   - 키워드 감지 `grep -qE` 패턴 추가
   - 해당 규칙 파일 읽기 블록 추가

**IF** 자동 주입이 불필요하면:
→ 이유를 결과 보고에 명시하고 이 단계는 생략합니다.

### 6. 검증

아래를 확인합니다.

```bash
test -f ".agents/rules/<file-name>.md"
rg -n "<새 규칙명|파일명>" .agents/INDEX.md
```

자동 주입 매핑을 수정한 경우 추가 검증:

```bash
rg -n "<키워드 또는 파일명>" .agents/skills/check-rules/SKILL.md .claude/hooks/check-rules.sh
```

### 7. 결과 보고

사용자에게 아래 항목을 짧게 보고합니다.

- 생성/수정된 파일 목록
- 새 규칙 핵심 요약 1~3줄
- 자동 주입 매핑 업데이트 여부
- 남은 확인 사항(있으면)

## 엣지 케이스

### Case: 규칙 제목은 한국어지만 파일명 규칙이 애매한 경우
→ 파일명은 영문 `kebab-case`로 만들고, 제목은 한국어를 유지합니다.

### Case: 기존 규칙과 중복/충돌되는 내용이 있는 경우
→ 신규 파일 생성 전에 기존 규칙 병합 또는 상위 규칙 참조 구조로 정리합니다.

### Case: 인덱스는 업데이트됐지만 키워드 매핑이 누락된 경우
→ `check-rules` 스킬/훅까지 즉시 동기화 후 완료 보고합니다.
