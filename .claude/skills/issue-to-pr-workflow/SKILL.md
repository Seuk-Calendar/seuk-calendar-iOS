# Issue To PR Workflow

GitHub 이슈 번호 하나를 기준으로 작업 시작부터 PR 생성까지 일관된 순서로 처리합니다.

## 입력

- 필수: 이슈 번호 (`<number>`)

## 실행 단계

### 1. 사전 점검 수행

1. `check-memory` 스킬을 먼저 실행해 재발 방지 체크리스트를 적용합니다.
2. `check-rules` 스킬을 실행해 커밋/PR/리뷰 규칙을 현재 요청 기준으로 요약합니다.
3. 작업 트리가 더럽거나(미커밋 변경 존재) 현재 브랜치 상태가 위험하면 먼저 사용자에게 진행 가능 여부를 확인합니다.

### 2. 이슈 내용 수집 및 작업 범위 확정

아래 명령으로 이슈 본문과 코멘트를 읽고 요구사항을 확정합니다.

```bash
gh issue view <number> --json number,title,body,labels,assignees,url
gh issue view <number> --comments
```

1. 이슈에서 구현 요구사항, 제외 범위, 완료 조건을 추출합니다.
2. 불명확한 요구사항이 있으면 구현 전에 사용자에게 짧게 확인합니다.

### 3. 브랜치 준비

이슈 번호를 포함한 브랜치를 준비합니다.

1. 브랜치가 없으면 먼저 `create-branch` 스킬을 사용해 브랜치를 생성합니다.
2. `create-branch` 실행 시 브랜치 컨벤션(`<타입>/#<이슈번호>-<설명>`)을 그대로 적용합니다.
3. 타입이 애매하면 `feat`를 기본으로 사용하고, 버그 수정이 명확하면 `fix`를 사용합니다.
4. `create-branch`를 사용할 수 없는 예외 상황에서만 직접 `git checkout -b`로 대체합니다.

### 4. 구현 및 문서 동기화

1. 이슈 본문 기준으로 코드를 수정합니다.
2. 아키텍처/모듈 구조/의존성이 바뀌면 다음 문서를 함께 업데이트합니다.
   - `.agents/rules/Architecture.md`
   - 해당 모듈의 `Module.md`

### 5. 품질 검증

1. 변경된 Swift 파일은 `format-swift` 스킬 또는 프로젝트 포맷터로 정리합니다.
2. 가능한 범위에서 빌드/테스트/린트를 실행합니다.
3. 실행 불가한 검증이 있으면 이유를 결과 보고에 남깁니다.

### 6. 커밋

커밋 컨벤션을 반드시 지켜 커밋합니다.

```text
#<이슈번호> <타입> :: <제목>
```

1. 의미 단위로 커밋을 분리합니다.
2. 제목/본문은 기본적으로 한국어로 작성합니다.

### 7. 코드 리뷰 실행 및 반영

1. `review-pr` 스킬로 현재 변경사항을 리뷰합니다.
2. 리뷰 Finding 중 `P0`, `P1`은 반드시 수정합니다.
3. `P2`는 가능한 범위에서 수정하고, 보류 시 근거를 정리합니다.
4. 수정 후 필요한 검증을 재실행합니다.

### 8. 잘못된 패턴 memory 기록

반복 가능성이 있는 실수, 사용자 교정 요청, 컨벤션 누락이 있으면 `write-memory` 스킬을 실행합니다.

1. `memory-template` 형식으로 신규 메모리를 작성합니다.
2. `MEMORY_INDEX.md`에 인덱스를 추가합니다.
3. 어떤 예방 규칙을 추가했는지 결과에 명시합니다.

### 9. PR 생성

`create-pr` 스킬로 PR을 생성합니다.

1. PR 제목은 PR 컨벤션 형식(`(#<이슈번호>) <제목>`)을 따릅니다.
2. 본문은 `.github/PULL_REQUEST_TEMPLATE.md` 구조를 유지합니다.
3. 원격 브랜치 미푸시 상태면 먼저 `git push -u origin <branch>`를 수행합니다.

## 결과 보고 형식

작업 종료 시 아래 항목을 순서대로 보고합니다.

1. 대상 이슈: 번호, 제목, URL
2. 브랜치명
3. 커밋 목록
4. 리뷰 Finding 반영 결과
5. memory 기록 여부(기록 파일명)
6. PR 번호와 URL

## 예외 처리

- 이슈가 존재하지 않으면 즉시 중단하고 사용자에게 알립니다.
- `gh auth` 또는 저장소 권한 문제가 있으면 인증/권한 상태를 먼저 해결합니다.
- 외부 변경(내가 만들지 않은 예상치 못한 변경)이 발견되면 작업을 멈추고 사용자 지시를 받습니다.
