# Commit Convention

## 형식

```
#<이슈번호> <타입> :: <제목>

<본문 (선택)>
```

## 타입

| 타입 | 설명 |
|------|------|
| feat | 새로운 기능 추가 |
| fix | 버그 수정 |
| env | 환경 설정, 빌드, CI/CD 관련 변경 |
| chore | 코드 변경 없는 잡무 (파일 정리, 설정 변경 등) |
| refactor | 기능 변경 없는 코드 리팩토링 |
| docs | 문서 추가 및 수정 |
| test | 테스트 추가 및 수정 |
| style | 코드 스타일 변경 (포맷팅, 세미콜론 등) |

## 예시

```
#312 env :: 커밋 규칙 문서 추가
#999 feat :: 어떠한 기능 구현
#100 fix :: 로그인 시 크래시 발생하는 문제 수정
#200 refactor :: 네트워크 레이어 구조 개선
```

## 규칙

- 커밋은 충분히 작은 단위로 나누어 작성한다.
- 커밋 제목과 본문은 기본적으로 한국어를 사용한다.
- 제목은 간결하게 작성하되, 변경 내용을 명확히 전달한다.
- 이슈번호는 반드시 포함한다.
