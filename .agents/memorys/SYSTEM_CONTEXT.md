# Memory System Context

## 문서 목적(Document Purpose)
이 문서는 `.agents/memorys` 기반 메모리 시스템이 왜 만들어졌는지, 어떤 문제를 해결하려는지, 현재 어떤 규칙으로 운영하려는지를 다른 에이전트에게 전달하기 위한 컨텍스트 문서입니다.

## 배경(Background)
프로젝트 진행 중 동일한 실수/안티 패턴(범위 외 변경 포함, 규칙 미적용, 컨텍스트 누락)이 반복되면서 작업 품질과 속도가 흔들리는 문제가 확인되었습니다.  
사용할수록 더 정확해지는 에이전트 환경을 만들기 위해, 실수/거부/교정 내역을 구조화된 문서로 축적하고 명령 전 검색하는 체계를 도입하기로 했습니다.

## 핵심 목표(Core Goals)
1. 명령 수행 전에 과거 메모리를 검색해 재발을 줄입니다.
2. 사용자 피드백(거부/수정 요청)을 구조적으로 축적합니다.
3. 프로젝트 컨벤션/의사결정 컨텍스트를 누적해 에이전트 정합성을 높입니다.

## 네이밍 결정(Naming Decisions)
- 기록 단위 이름은 `incident`가 아니라 `memory`를 사용합니다.
- 시스템 디렉토리는 `.agents/memorys`를 사용합니다. (의도된 프로젝트 컨벤션)
- 각 메모리는 `.md` 파일 1개로 관리합니다.

## 메모리 포맷 규칙(Memory Format Rules)
- 섹션은 모두 `##`를 사용합니다.
- 섹션명은 `한글(English)` 형식으로 작성합니다.
- 메모리에는 키워드 기반 검색을 위한 `## 키워드(Keywords)` 섹션이 반드시 포함되어야 합니다.
- 메모리에는 실행 전 확인 가능한 `## 사전 점검(Pre-Command Check)`가 포함되어야 합니다.

## 운영 흐름(Operational Flow)
1. 사용자 명령 수신
2. `check-memory` 계열 로직을 항상 호출하여 `.agents/memorys` 검색
3. 관련 메모리 기반 사전 점검 체크리스트 생성
4. 명령 수행
5. 실수/거부/중요 교훈 발생 시 `write-memory`로 신규 메모리 기록
6. 기록 완료 사실을 사용자에게 출력으로 알림

## 정책(Policies)
- 노이즈 방지: 재발 가능성/비용이 낮은 사소한 이벤트는 기록하지 않습니다.
- 사용자 알림: 메모리 기록 시 사용자에게 반드시 알립니다.

## 현재 범위(Current Scope)
- 포함:
  - 메모리 검색 기반 사전 점검
  - 메모리 작성 표준화
  - 키워드 기반 검색 가능성 확보
- 보류:
  - 동일 실수 반복 시 강제 규칙
  - 오래된 메모리 정리 주기
  - 효과 측정 지표 운영

## 권장 메모리 항목(Recommended Memory Fields)
- 제목/날짜/유형/키워드/컨텍스트
- 문제 행동/사용자 피드백/원인
- 예방 규칙/사전 점검
- 금지 동작/안전 대안/검증 단계
- 적용 범위/심각도
- 예시(나쁜 예/좋은 예)
- 관련 메모리 링크

## 유지보수 지침(Maintenance Guidance)
- 이 문서는 시스템 방향이 바뀔 때마다 업데이트합니다.
- 세부 포맷은 템플릿 문서(예: `templates/memory-template.md`)로 분리해 운영합니다.
- 실제 운영 규칙이 문서와 충돌하면 최신 사용자 지시를 우선합니다.
