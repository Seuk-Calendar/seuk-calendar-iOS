# GitHub Issue Creation

GitHub 이슈를 자동으로 생성하는 스킬입니다.

## 트리거 조건

다음 상황에서 이 스킬을 **자동으로** 실행:

1. 사용자가 명시적으로 이슈 생성 요청 ("이슈 추가해줘", "깃허브 이슈 만들어줘")
2. 사용자가 새로운 작업/기능을 계획할 때

## 실행 단계

### 1. 이슈 템플릿 확인

이슈 템플릿 존재 여부 확인 (디렉토리 구조와 파일 형식 모두 지원):

```bash
# 디렉토리 형식 또는 단일 파일 형식 모두 확인
if [ -d .github/ISSUE_TEMPLATE ]; then
  ls -la .github/ISSUE_TEMPLATE/
elif [ -f .github/ISSUE_TEMPLATE.md ]; then
  ls -la .github/ISSUE_TEMPLATE.md
else
  echo "No issue templates found"
fi
```

**IF** 템플릿이 여러 개 존재 (.github/ISSUE_TEMPLATE/ 디렉토리 내 여러 파일):
→ 작업 내용에 맞는 템플릿 선택 (bug.yml, todo.yml 등)

**IF** 템플릿이 없음:
→ 기본 이슈 형식 사용

### 2. 기존 이슈 중복 확인

관련 이슈가 이미 존재하는지 확인:

```bash
# 오픈된 이슈 목록 확인
gh issue list --limit 20

# 키워드로 검색
gh issue list --search "{키워드}" --limit 10
```

**IF** 관련 이슈 발견:
→ 사용자에게 기존 이슈 정보 제공하고 새 이슈 생성 필요성 확인

### 2-1. 현재 저장소 라벨 확인

이슈 생성 전에 현재 저장소 라벨을 확인합니다:

```bash
gh label list --limit 200
```

현재 저장소에서 사용하는 주요 라벨:

- `📋 TODO`: 일반 작업, 기능 추가, 후속 할 일
- `🐞 BUG`: 버그 수정
- `Enhancement`: 개선, 리팩터링, 품질 향상
- `🎨 DESIGN`: 디자인, 피그마, UI 시안 관련 작업
- `AI Environment`: 스킬, 룰, 마크다운 등 AI 에이전트 작업 환경 관련 변경

**중요**:
- 사용자가 라벨을 지정하면 저장소에 실제로 존재하는 라벨인지 먼저 확인
- 존재하지 않는 라벨명을 임의로 생성하거나 추측해서 사용하지 않음
- 요청 의도와 현재 라벨이 다르면 가장 가까운 기존 라벨을 제안하거나 사용자에게 확인

### 3. 사용자 확인

**사용자에게 질문**:
```
이 작업을 GitHub 이슈로 생성할까요?

작업 내용: {작업 요약}
```

**IF** 사용자가 거부:
→ 이슈 생성 중단

**IF** 사용자가 동의:
→ 다음 단계 진행

### 4. 이슈 본문 구성

**IF** 템플릿 존재:
→ 템플릿 내용을 기반으로 본문 작성

**ELSE**:
→ 기본 형식 사용:

```markdown
## 작업 내용

{작업에 대한 명확한 설명}

## 상세 설명

{구체적인 요구사항이나 구현 방향}

## 체크리스트

- [ ] 작업 항목 1
- [ ] 작업 항목 2
- [ ] 작업 항목 3

## 참고사항

{추가적인 컨텍스트나 참고 자료}
```

### 5. 이슈 생성

GitHub CLI로 이슈 생성 (기본적으로 작성자를 assignee로 지정):

```bash
gh issue create --title "{제목}" --body "{본문}" --assignee "@me"
```

**추가 선택 사항**:
- 라벨 추가: `--label "Enhancement"`
- 마일스톤: `--milestone "v1.0"`

### 6. 생성 완료 보고

**사용자에게 보고**:
```
✅ 이슈가 생성되었습니다!

📋 이슈 정보:
- 번호: #{이슈번호}
- 제목: {제목}
- URL: {이슈 URL}
```

## 엣지 케이스

### Case: 템플릿이 여러 개인 경우
→ AskUserQuestion 도구로 사용자에게 템플릿 선택 요청

### Case: GitHub CLI 인증 안 됨
→ `gh auth status` 확인 후 사용자에게 인증 요청

### Case: 저장소 권한 없음
→ 권한 오류 메시지를 사용자에게 전달

### Case: 제목이 너무 길 경우
→ 50자 이내로 요약하고 나머지는 본문에 포함

### Case: 이슈 번호를 브랜치명에 사용해야 하는 경우
→ 이슈 번호를 변수로 저장하여 후속 작업에 활용 가능하도록 제공
